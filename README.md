# Northstar Job Application Tracker

A complete full-stack job application tracker using Java 17 core libraries and a vanilla HTML/CSS/JavaScript dashboard. The backend uses `com.sun.net.httpserver.HttpServer`; it has no Spring Boot, Maven, Gradle, or third-party dependencies.

## Requirements

Install a JDK 17 or newer and make sure `java` and `javac` are on your PATH. Run all commands from the project root.

## Compile

Windows PowerShell:

```powershell
New-Item -ItemType Directory -Force -Path out | Out-Null
javac -d out src\*.java
```

macOS/Linux:

```bash
mkdir -p out
javac -d out src/*.java
```

## Run

```powershell
java -cp out Main
```

Open <http://localhost:8080>. To use another port, pass it as the first argument:

```powershell
java -cp out Main 9090
```

The API persists every change immediately to `data/jobs.json`.

## Deploy from GitHub

GitHub Pages can host the frontend, but it cannot run the Java `HttpServer`. For a fully functional public deployment, deploy the backend from this repository to a Docker-capable host with persistent storage, then deploy the frontend to GitHub Pages.

### 1. Push the project to GitHub

Create an empty GitHub repository, then run:

```powershell
git init
git add .
git commit -m "Initial job tracker"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/YOUR-REPOSITORY.git
git push -u origin main
```

### 2. Deploy the Java backend

Use the repository's `Dockerfile` with a Docker-capable service such as Render, Railway, Fly.io, or Azure Container Apps. Configure the service to expose its `PORT` environment variable and attach persistent storage for `/app/data`; the application stores jobs in `/app/data/jobs.json`.

The backend must be publicly reachable at a URL such as `https://your-api.example.com`. CORS is enabled for the frontend deployment.

### 3. Enable GitHub Pages

In GitHub, open **Settings > Pages**, choose **GitHub Actions** as the source, and make sure the repository's default branch is `main`. The included `.github/workflows/deploy-pages.yml` publishes the `web` folder after every push.

Add a repository variable under **Settings > Secrets and variables > Actions > Variables**:

```text
Name: BACKEND_URL
Value: https://your-api.example.com
```

The workflow writes that value into `web/config.js`, so the hosted dashboard calls `https://your-api.example.com/api/jobs`. Never add credentials or private tokens to this variable.

The included `build.yml` compiles the Java 17 backend on every push and pull request.

### Local versus hosted behavior

Locally, `web/config.js` is empty and the browser uses the same-origin API at `/api/jobs`. On GitHub Pages, the workflow injects `BACKEND_URL` so all add, edit, delete, search, filter, sort, statistics, loading, error, and empty states continue to use the live backend.

## API

- `GET /api/jobs` returns all applications.
- `GET /api/jobs/{id}` returns one application.
- `POST /api/jobs` creates an application.
- `PUT /api/jobs/{id}` replaces an application.
- `DELETE /api/jobs/{id}` removes an application.

JSON fields are `id`, `company`, `role`, `location`, `salary`, `applicationUrl`, `status`, `dateApplied`, and `notes`. `company`, `role`, `status`, and `dateApplied` are required. Allowed statuses are `Applied`, `Interview`, `Rejected`, and `Offer`.

## Testing

1. Compile using the command above.
2. Start the server with `java -cp out Main`.
3. Open the dashboard and create, edit, search, filter, sort, and delete an application.
4. Confirm persistence by stopping and restarting the server.
5. Optional PowerShell API smoke test:

```powershell
$body = @{ company='Acme'; role='Engineer'; location='Remote'; salary='$120k'; applicationUrl='https://example.com/jobs/1'; status='Applied'; dateApplied='2026-09-27'; notes='Follow up next week' } | ConvertTo-Json
Invoke-RestMethod -Uri http://localhost:8080/api/jobs -Method Post -ContentType 'application/json' -Body $body
Invoke-RestMethod -Uri http://localhost:8080/api/jobs -Method Get
```
